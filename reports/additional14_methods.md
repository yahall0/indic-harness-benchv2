# Expansion under the original evaluation protocol

The first campaign contains 40 original tasks, each attempted once in English, Hindi and Hinglish: 120 stored attempts. Four infrastructure failures affect four distinct task triplets; the remaining 36 triplets have an agent outcome in all three conditions. Budget exhaustion remains an agent outcome and is not removed to improve results. Infrastructure failures remain recorded as missing observations for the primary paired analysis.

The user requested 10 additional original tasks to meet a 50-sample mid-semester requirement, then requested four further tasks to account for the infrastructure-incomplete triplets. The resulting design has 54 original tasks and 162 single-attempt language conditions. Exactly 14 new tasks and 42 new attempts are added. If every addition has an agent outcome in all three languages, the primary paired analysis will contain 50 complete original-task triplets. That count is not guaranteed if further infrastructure failures occur. The experimental unit is the original task; language conditions and individual instruction rounds are not independent samples.

The additions were selected after the original campaign ended and before observing their own model outcomes. Selection uses offline feasibility, small fixture size, category coverage and successful validation of the original oracle. It does not condition on model passing, failure or score. This dataset expansion must be disclosed; the entire 54-task dataset was not selected before observing any study outcomes. All original attempts, including infrastructure failures, remain in the journal and reporting. Never describe the four additions as successful-score replacements.

The additions cover all eight original families. The first 40 had five tasks per family; the expanded set has seven per family for six families and six per family for Vertical Professional Workflows and Long-running Autonomy & State Adaptation. Overall means retain the original task weighting; categories are reported with their denominators. The expanded category distribution is not exactly balanced, and results do not establish broad Indic-language generalization.

The same GPT-OSS-20B, OpenClaw 2026.9.7, temperature 0, medium reasoning effort, tools, system configuration and inference relay are used. Protocol revision remains 2. Every attempt retains min(original timeout, 600 seconds), 30 physical inference requests, a cumulative conservative 200,000 input-token allowance, 16,000 output-token allowance and a 4,096-token response limit, with at most two transient transport retries. State persists between rounds within one attempt and is reset between languages. The sole two-round addition, task 103, shares those budgets across both rounds. No new model, LLM judge, response allowance or language-specific accommodation is introduced.

The same credential handling remains in place: up to four eligible anonymous slots, no advance cycling on generic errors, switching only on explicit quota exhaustion, durable slot state and no automatic paid purchase. Language-order rotation continues at global task index 40; existing terminal attempts are skipped. The controller preserves the study ID while recording a new runtime freeze hash for the append-only extension. New attempts are stored in the same journal, checkpoint scheme, artifact layout and CSV/JSONL analysis as original attempts.

Original deterministic oracles and scores remain primary. Added integrity checks are reported separately. The private grader image is extended to include the new fixtures and private validation solutions; the agent, relay and helper images are unchanged. All 14 additions passed constructed correct-workspace, missing-output, meaningful incorrect-output and forbidden-edit checks in isolated Docker. The new grader also passed all original 40 validation cases without changing their original validation records. No task code, hooks or oracle were executed on Windows or ordinary WSL. Correct workspaces were AI-constructed and were not independently human-validated.

English instructions preserve source bodies. Hindi and Hinglish translate instruction bodies only, preserving technical literals; fixtures and English prose-output contracts remain identical across conditions. Task 048's original body says three artifacts while listing five; a shared suffix clarifies all five. Task 068's original body says three segments while the fixture contains four; the identical suffix requires addressing all listed segments and explaining the unavailable segment's exclusion. These clarifications do not supply a solution and are identical across all language conditions. Translation is complete with GPT-6 Luna AI self-review and a final AI check by GPT-6.1 Sol, rather than independent human validation. Two pre-freeze wording corrections preserve the workflow subject in task 044 and the strict cost boundary in task 065.

All additions use local files; no new public services or tunnels are required. Docker isolation remains non-root, read-only root, dropped capabilities, no-new-privileges, seccomp, 2 CPUs, 3 GiB RAM, 256 PIDs and a bounded 512 MiB workspace. Agent containers receive no Windows bind mounts, host drives, Docker control interfaces, credentials or protected grader files. Safe artifact export and separate network-isolated grading remain unchanged.

Primary estimates use complete matched triplets and the same English-minus-Hindi and English-minus-Hinglish completion and oracle-score differences. Bootstrap uncertainty uses original tasks as matched resampling units, the same 10,000 samples and seed 20260930. All attempted conditions, incomplete triplets, infrastructure classifications, budget exhaustion and available token/latency/tool measurements are reported. A successful extension adds observations; it does not turn the exploratory, one-attempt study into a confirmatory or tokenizer-causal experiment.

Before the extension, infrastructure events from the original campaign were reviewed: one local settlement acknowledgment failure after upstream HTTP 200, one HTTP 500 after both allowed retries, and two ambiguous transport failures at approximately 120 seconds. The existing pinned relay already supports idempotent local accounting retries. The controller saves and cleans up settled provider failures, applies the existing 30-second cooldown, then continues; three consecutive provider failures pause the session. This preparation does not increase the 120-second transport wait, model budgets, retry count or outcome-attempt count. Server availability cannot be guaranteed, and ambiguous requests are not replayed. Controller JSON and access-log reads now explicitly use UTF-8 on Windows; prompt reads already did so. This corrects host decoding without changing inference payloads or experimental budgets.
