routing_decisions.json requirements:
- Valid JSON array हो जिसमें tickets.json के हर ticket id के लिए **exactly one object** हो (IDs same हों; same ordering ज़रूरी नहीं).
- हर object में ये keys **zaroor** हों (order id न दिया हो तो empty string `""` use करें): ticket_id, action, policy_basis, order_id, priority, customer_reply_key.
- action ∈ { refund, reship, escalate_human, information_request }.
- policy_basis में governing clause token हो (REFUND-1, SHIP-1, ESC-1, INFO-1, FRAUD-1, CONFLICT-1, DISPUTE-1). Semicolon text से multiple citations दे सकते हैं, पर tooling checks के लिए सूची में दिया primary clause ID string ज़रूर होना चाहिए.
- Conflicts को सावधानी से सुलझाएँ: fraud holds, carrier/system contradictions के muqable warehouse facts, और DISPUTE-1 window के अंदर delivered-status POD disputes — VIP कुछ और kahe तब भी escalate_human.
- Verification missing हो → information_request + INFO-1.
- priority ∈ { high, normal }. हर escalate_human ticket के लिए और verification के बिना VIP-backed INFO-1 threads के लिए (policy VIP-1) **high** use करें.
- हर ticket के लिए customer_reply_key exactly एक stable snake_case identifier हो (templates में वही key use हो).

reply_templates.md requirements:
